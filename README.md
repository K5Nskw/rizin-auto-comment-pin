# rizin-auto-comment-pin

YouTube / TikTok に動画を投稿したら、**自動でコメントして、そのコメントをピン留めする**ツールです。
コメント文は管理画面からいつでも変更でき、動画のタイトルによって文面を出し分けたり、
複数パターンをランダムで使い分けたりできます。

サーバーは Railway で動かす前提で作ってあります。

---

## ⚠️ 最初に読んでください（各サービスの制約）

作り始める前に YouTube と TikTok の公式 API を調べた結果、**「ピン留め」を行う公式 API はどちらにも存在しません。**
TikTok には「自分の動画に通常コメントを投稿する API」もありません。

| やりたいこと | YouTube | TikTok |
|---|---|---|
| 新着動画の検知 | ✅ 公式API（push通知で即時） | ✅ 公式API（ポーリング） |
| コメントを投稿 | ✅ 公式API (`commentThreads.insert`) | ❌ 公式APIなし |
| コメントをピン留め | ❌ 公式APIなし | ❌ 公式APIなし |

そのため、このツールは **2階建て** の構成になっています。

1. **APIでできること** → 公式APIで確実に実行（新着検知・YouTubeのコメント投稿）
2. **APIでできないこと** → 自分のログイン済みCookieを使ってブラウザ画面を自動操作（ピン留め・TikTokのコメント投稿）

**2 は各サービスのUI変更で動かなくなる可能性があります。** 壊れたときに気づけるよう、
失敗時は通知が飛び、失敗した瞬間の画面スクリーンショットが管理画面に残ります。
また、ブラウザ自動操作を使わない設定（`ENABLE_BROWSER_AUTOMATION=false`）にすると、
YouTubeのコメント投稿までを自動で行い、ピン留めは「手動でやってください」という通知だけを送ります。

> 自分名義のアカウントで、自分の動画に、自分のコメントをピン留めする用途を想定しています。
> 各サービスの利用規約は自動化について明確でない部分があるため、業務利用の前に一度ご確認ください。

## コメント文の変え方

管理画面の **「コメント文の編集」** タブで、いつでも変更できます（再デプロイ不要）。

- **複数パターンのランダム投稿** … 1つのテンプレートに文面を複数登録すると、投稿のたびにランダムで選ばれます
- **タイトルによる出し分け** … 「ハイライト」を含む動画とそれ以外で別の文面、といった条件分岐
- **変数の差し込み** … `{{title}}` `{{url}}` `{{date}}` など
- **文中のランダム** … `[[最高でした|痺れました|圧巻でした]]` のように書くと、その部分だけランダムに変わります
- **プレビュー** … 「このタイトルの動画が来たら実際に何が投稿されるか」を保存前に確認できます

詳しくは [docs/TEMPLATES.md](docs/TEMPLATES.md) を参照してください。

## 安全装置

うっかり大量投稿してしまわないように、以下の仕組みが入っています。

| 仕組み | 内容 |
|---|---|
| **基準時刻（watermark）** | **ツールを有効化した時刻より後に公開された動画にしかコメントしません。** 初回検知時にその時刻を記録し、既に公開済みだった動画は対象外になります。管理画面から現在時刻にリセットできます |
| 公開日時が不明な動画 | 新着か過去のものか判別できないため、コメントしません |
| `MAX_VIDEO_AGE_HOURS` | 補助的な安全装置。公開から既定48時間より古い動画にはコメントしません（長期停止後に古いキューが動くのを防ぎます） |
| 1動画1ジョブ | DBのユニーク制約で、同じ動画に2回コメントすることが構造的に起きません |
| 取り消し | 投稿済みコメントを管理画面からYouTube上から削除できます |
| `DRY_RUN=true` | 検知と文面生成だけ行い、実際には投稿しません。テスト用 |
| 公開状態の確認 | YouTubeでは限定公開・非公開の間は投稿せず、公開されるまで待機します |
| リトライ上限 | 5回失敗したら諦めて通知します（無限リトライしません） |

## 主な環境変数

すべて `.env.example` に説明付きで記載しています。特に重要なもの：

| 変数 | 説明 |
|---|---|
| `PUBLIC_URL` | Railway で発行した https のURL。OAuthとpush通知に使うため必須 |
| `DATABASE_URL` | Railway で Postgres を追加すると自動で入ります |
| `ADMIN_USER` / `ADMIN_PASSWORD` | 管理画面のログイン。**必ず設定してください**（未設定だと誰でも開けます） |
| `ENCRYPTION_KEY` | トークンとCookieの暗号化キー。`openssl rand -hex 32` で生成 |
| `ENABLE_BROWSER_AUTOMATION` | `false` にするとピン留めを行わず通知のみになります |
| `NOTIFY_WEBHOOK_URL` | Discord / Slack の Incoming Webhook。失敗時や手動対応が必要なときに飛びます |

## ローカルで動かす

```bash
npm install
cp .env.example .env    # DATABASE_URL などを埋める
npm run dev
# http://localhost:3000/admin/
```

ローカルでは `PUBLIC_URL` が http のため YouTube の push 通知は使えません（ポーリングのみで動作します）。

## トラブルシューティング

**コメントは投稿されるがピン留めされない**
「アカウント連携」タブ →「失敗時の画面を見る」でスクリーンショットを確認してください。
「ログイン確認」が失敗する場合は Cookie の期限切れです。登録し直してください。

**新着が検知されない**
ダッシュボードで「即時通知」が有効か確認 →「YouTube 即時通知を再購読」を実行。
それでも駄目なら「今すぐ新着チェック」でポーリングが動くか確認してください。

**`quotaExceeded` が出る**
YouTube API の1日あたりの上限（既定10,000ユニット）です。コメント投稿1回で50ユニット消費します。
通常の投稿頻度なら十分足りますが、必要なら Google Cloud Console から上限緩和を申請してください。

**ピン留めが動かなくなった（UI変更）**
`src/browser/youtube.ts` / `src/browser/tiktok.ts` のセレクタを更新してください。
エラーメッセージにどの手順で失敗したかが出ます。

## 構成

```
src/
  index.ts              起動
  config.ts             環境変数
  pipeline.ts           検知 → テンプレート選択 → ジョブ作成（全経路がここを通る）
  worker.ts             ジョブ実行・リトライ・手動フォールバック
  scheduler.ts          定期実行
  templates/            テンプレートエンジン（変数展開・条件マッチ）
  platforms/youtube/    OAuth / Data API / RSS / WebSub
  platforms/tiktok/     OAuth / Display API
  browser/              Playwright によるピン留め・TikTokコメント
  web/                  管理画面 + API
  db/                   スキーマとクエリ
```
